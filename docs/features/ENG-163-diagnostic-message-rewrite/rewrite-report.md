# ENG-163 Rewrite Report

Every message template tiger prints, before and after, with the blind reader's answers for each
"after". The style guide is ADR-0009 and the specification's "Diagnostics" section. Templates with
interpolated arguments show one representative instantiation from the corpus (or, for the golangci
audit, from the `internal/golangci/testdata/fixtures/audit` config).

## Blind-reader protocol

Each "after" went to a sub-agent (Claude Sonnet) as message text only: no source, no
specification, no glossary, no "before", no tools. It answered "(a) What did the code do wrong?
(b) What exact edit fixes it?" and named anything unclear. Ten readers took eight messages each in
round one; the misses went to a fresh reader in round two with the reworded text. The table shows
the final round's answers, condensed but faithful.

Round-one misses and what changed:

- The three facts-channel lines (`TS-F01`, `TS-F07`, `TS-V01` under `--show-facts`) read as
  required edits: "to freeze that, add `//tiger:frame r.log`" became "missing the required
  comment" in both readers' (a). Reworded to "nothing to fix; to make tiger fail the build if
  that changes, add `//tiger:frame r.log`". Round two: both readers answered "nothing is wrong".
  The directive stays last on the line because `TestFactsRoundTrip` reparses everything from
  `//tiger:` to end of line.
- The golangci absent-setting line ("statements isn't set, so funlen doesn't enforce hard limit
  of 70 lines per function — set it to 45") left the reader unable to reconcile 70 with 45. Now
  quotes the rule title and names the setting in the edit. Round two: pass.
- `TS-S21`'s "add `const _ = uint(<relation>)`" was opaque. Now shows a concrete relation
  (`const _ = uint(bufferSize - batchMax)`) and says it stops compiling once the limit outgrows
  its bound. Round two: the reader explained the underflow mechanism back correctly.
- Two clarity nits: `-allow=preparing` and `-supervisors` are now called flags.
